```javascript
  body: JSON.stringify({
    model: "claude-sonnet-4-6",
    system: `あなたはこのリポジトリの設計者の代理として質問に答えます。\n\n---\n${repoContent}\n---`,
    messages: [{ role: "user", content: "こんにちは" }]
  })
});
```

- メリット：ネットワーク不安定性やツール権限の問題を一切気にせず、確実に動く
- デメリット：READMEが更新されても再取得ロジックを別途走らせる必要がある

## パターンB：ChatBot自身にリポジトリを読ませる（構想により忠実）

「ユーザーが送信すると、ChatBotがREADMEを読みに行く」を文字通り実装するなら、AIにツール（bashやgit clone相当のfunction）を持たせるagentic方式です。これはClaude Agent SDK（旧Claude Code SDK）を使うのが自然で、まさに今私がbashツールでリポジトリをクローンしたのと同じことをアプリ内で行わせられます。

```javascript
// Agent SDK的な擬似コード
const session = await ClaudeAgent.start({
  systemPrompt: "起動したら、まずghostリポジトリをcloneしてREADME.mdを読み、その内容を理解してからユーザーの質問に答えてください。",
  tools: ["bash"], // git clone, cat 等を実行できる
});
```

これなら「起動 → 指示文送信 → READMEを自分で読む → 以降は普通のセッション」というユーザーが描いた流れをそのまま実装できます。ghostプロジェクトがすでにClaude Codeベースなので、親和性が高いはずです。

## どちらを選ぶか

- 単一の固定リポジトリに対するQ&Aボットなら**パターンA**で十分（速い・安い・シンプル）
- 「設計者の代わりに答える」を汎用化して複数リポジトリ・複数ghostに対応させたいなら**パターンB**（ghostの思想である「AIエージェント同士が取材する」構想に発展させやすい）

docs/idea.ja.mdやCLAUDE.mdも読んでみましょうか？もう少し具体的な設計意図（DJCフレームワークとの絡みなど）を踏まえた実装案に落とし込めるかもしれません。
